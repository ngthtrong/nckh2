\subsection*{Objective}
Develop a prototype for receiving, analyzing and consolidating flood-rescue reports under intermittent connectivity, combining edge inference, compact transmission and a dispatch dashboard.
\subsection*{Methods}
A fixed image split supports classification and comparisons of runtime formats, quantization and structured pruning. An observable graph and bounded priority pipeline is assessed through separate synthetic clustering, ranking and dispatch studies. The Flutter application and FastAPI backend implement persistent queues, adaptive sending, retry and a versioned synchronization contract.
\subsection*{Findings and outputs}
The current FP32 image model achieves \ImageAccuracy\% accuracy and \ImageMacroFOne\% macro-F1 on \ImageTest{} held-out images. ONNX and ExecuTorch match PyTorch top-1 predictions on this split. PTQ reduces file size with an accuracy trade-off; the recorded QAT branch performs poorly. A structured urgency LR model uses a deterministic 32-state synthetic reference table, rather than Vietnamese free-text understanding or clinical ground truth.

The repository contains the application, backend, map dashboard, model artifacts and a research manuscript. Conditional edge bounds and exact-copy score invariance do not establish general clustering, ranking or dispatch superiority. Synthetic outcomes and CPU timings provide diagnostics, not evidence of field rescue benefit.
PTQ/QAT summary metrics have disclosed prediction-CSV discrepancies and require reconciliation before being finalized.
\subsection*{Application scope and follow-up}
The prototype supports research and workflow demonstration. Independent field data, expert validation, text modeling, urgency-field integration, Android measurements and operational network/SMS testing remain necessary.
